# TTL467 Language Reference

TTL467 describes immutable tensor computations: a bound value cannot be changed.

## 1. Language scope

The language has static named axes, globals, exported functions, and immutable
bindings. Static means known at compile time; intrinsics are built-in operations.
Its operations are element-wise intrinsics, einsum, constant selection,
gather, and axis renaming/merging. Only the types and operations defined here
are supported. There are no dynamic axes, loops, recursion, calls between
exports, mutation, or implicit type conversions.

## 2. A complete program

```ttl
axis row := 3, shared := 5, column := 4;
export function gemm(a: f32[row shared], b: f32[shared column])
    -> f32[row column] :=
    let
        %0 = @einsum[row shared, shared column -> row column](a, b)
             map=@multiply_f32 reduce=@add_f32
    in %0;
```

This program multiplies a 3-by-5 matrix by a 5-by-4 matrix. Axis names identify
coordinates shared between operands. `%0` names an immutable result; an ordinary
name such as `product` is also valid. Independent computations may be evaluated
in any dependency-preserving order.

## 3. Tokens and grammar

### Tokens

Source text consists of ASCII characters. Whitespace consists of space, tab,
line feed, carriage return, form feed, and vertical tab. Whitespace and comments
separate tokens and are otherwise ignored.
Comments are `//` through end of line and non-nesting `/* ... */`.
An unterminated block comment is an error.

The complete set of fixed tokens is:

| Category | Token spellings |
| --- | --- |
| Keywords | `axis` `global` `export` `function` `let` `in` `map` `reduce` `inf` `true` `false` |
| Two-character symbols | `:=` `->` |
| One-character symbols | `(` `)` `[` `]` `:` `;` `,` `=` `-` `*` |

Each spelling in the table is one token. The remaining token classes are
defined by these regular expressions:

```text
id       = [A-Za-z_][A-Za-z0-9_]*
integer  = 0|[1-9][0-9]*
float    = ([0-9]+\.[0-9]*|\.[0-9]+)([eE][+-]?[0-9]+)?
         | [0-9]+[eE][+-]?[0-9]+
at-id    = @[A-Za-z_][A-Za-z0-9_]*
perc-id  = %(0|[1-9][0-9]*)
```

Use longest matches, preferring keywords over `id`; keywords cannot be identifiers.
Type names (`f32`, `i32`, `bool`) are `id`; intrinsic names are `at-id`.
Neither `% 0` nor `@ add_f32` is valid. Integers and percent identifiers cannot
have leading zeroes. Minus is separate in `-1.0`, but part of the float in `1e-3`.
Comment delimiters are not tokens. No other symbol tokens exist: `+`, for example,
occurs only inside a float exponent.

### Grammar

Quoted strings denote the fixed tokens above, without the quotes. The five
token-class names refer to their regular expressions. `EOF` denotes end of input;
other names denote grammar rules. Outside quotes, `|` means alternative,
parentheses group, and suffixes `?`, `*`, `+` mean optional, zero or more, and
one or more. Thus `"*"` is a token; `dimension*` is a sequence of dimensions.

```ebnf
program     ::= axis-decl* global* function+ EOF ;
axis-decl   ::= "axis" id ":=" integer ("," id ":=" integer)* ";" ;
global      ::= "global" id ":" type ";" ;
function    ::= "export" "function" id "(" (param ("," param)*)? ")"
                "->" results ":=" expr ";" ;
param       ::= id ":" type ;
results     ::= type | "(" type ("," type)+ ")" ;
type        ::= id ("[" dimension* "]")? ;
dimension   ::= id (":=" integer)? ;
value       ::= id | perc-id ;
result      ::= value | "(" value ("," value)+ ")" ;
expr        ::= result | "let" binding (";" binding)* "in" result ;
binding     ::= value "=" (literal | "-" (integer | float | "inf")
                          | value selector | primitive) ;
literal     ::= integer | float | "inf" | "true" | "false" ;
selector    ::= "[" selection ("," selection)* "]" ;
selection   ::= id "=" integer (":" integer)? ;
primitive   ::= at-id ("[" axis-spec "]")?
                "(" value ("," value)* ")" clauses ;
clauses     ::= (map-clause reduce-clause? | reduce-clause map-clause?)? ;
map-clause  ::= "map" "=" at-id ;
reduce-clause ::= "reduce" "=" at-id ;
axis-spec   ::= pattern ("," pattern)* "->" pattern ;
pattern     ::= (id | id ":=" integer | id ":=" "[" id ("*" id)+ "]")* ;
```

## 4. Types, names, and shapes

The dtypes are `f32` (IEEE binary32), `i32` (signed 32-bit integer), and
`bool`. A scalar has no axes: `f32` and `f32[]` are the same type.
Integer, floating, and Boolean literals have types i32, f32, and bool respectively.

Static axis extents are integers in 1..2147483647. Every axis is declared
exactly once. `f32[row column]` uses the declared extents;
`f32[row := 2 column]` gives that occurrence of row extent 2.
Inline extents do not declare or rename axes.

Types compare dtype, named axes, and extents, not axis order:
`f32[row column]` and `f32[column row]` are equal. Equal extents do not make
different axes equal. A type cannot repeat an axis.

Axes, exports, and values have separate namespaces. Globals are immutable module
inputs, fixed for a module instance. Global and export names must each be unique.
Within an export, parameters and bindings are unique and cannot shadow globals.
Values refer to globals, parameters, or earlier bindings; forward references are
forbidden. Local names are independent between exports. Percent names may name
only local bindings.

Each primitive produces one value. Export results are ordered value references;
their inferred types and count must match the declaration. Bindings infer types
from operands and operations, not from the export's result annotation.

Nonnegative i32 literals are at most 2147483647; negative magnitudes may be
1..2147483648. Convert decimal floats to binary32, round-to-nearest ties-to-even.
Overflow/underflow follow that conversion. `inf` and `-inf` are f32 infinities;
there is no NaN literal.

## 5. Element-wise operations and broadcasting

A scalar operation applies independently at each coordinate. Its result axes
are the union of operand axes. Shared axis names must have equal extents.
An operand missing an axis broadcasts along it. A scalar therefore broadcasts
over every tensor axis. An extent-one axis is not automatically broadcast to
a different extent under the same name.

For `x, y: f32[item]` and scalar `scale = 1.25`, the bindings
`product = @multiply_f32(scale, x); result = @add_f32(product, y)` mean:

```c
for (int item = 0; item < ITEMS; ++item)
    result[item] = 1.25f * x[item] + y[item];
```

For `matrix: f32[row column]` and `bias: f32[column]`,
`@add_f32(matrix, bias)` broadcasts bias over row:

```c
for (int row = 0; row < ROWS; ++row)
    for (int column = 0; column < COLUMNS; ++column)
        sum[row][column] = matrix[row][column] + bias[column];
```

In all C examples, uppercase names denote extents and subscripts indicate array
dimensions. These examples specify values, not storage or execution order;
each result is immutable despite the C assignment notation.

These are the complete supported scalar intrinsics:

| Name | Input types -> result | Meaning |
| --- | --- | --- |
| @add_f32, @subtract_f32, @multiply_f32, @divide_f32 | f32, f32 -> f32 | arithmetic |
| @negate_f32 | f32 -> f32 | unary minus |
| @minimum_f32, @maximum_f32 | f32, f32 -> f32 | minimum, maximum |
| @greater_f32 | f32, f32 -> bool | greater than |
| @exp_f32, @exp2_f32 | f32 -> f32 | powers of e and 2 |
| @log_f32, @log2_f32 | f32 -> f32 | logarithms |
| @ceil_f32 | f32 -> f32 | ceiling, still represented as f32 |
| @rsqrt_f32 | f32 -> f32 | reciprocal square root |
| @cast_i32_f32 | i32 -> f32 | explicit conversion |
| @select_f32 | bool, f32, f32 -> f32 | choose second if true, third otherwise |
| @select_i32 | bool, i32, i32 -> i32 | same |
| @select_bool | bool, bool, bool -> bool | same |

Direct applications have no axis specification, map clause, or reduce clause.
Select is element-wise selection, not short-circuit control flow: its operands
are already defined values. Intrinsic arguments must match their fixed types.

## 6. Einsum

`@einsum` has one input pattern per operand, followed by its output pattern.
Patterns here contain only bare axis names. Each input pattern names exactly
its operand's axes, without duplicates. All shared extents must match.

1. Form the union of input axes.
2. Output axes are distinct members of that union.
3. Axes absent from the output are reduction axes.
4. Broadcast operands missing an iteration axis, then apply map at each coordinate.
5. Reduce the mapped values for each output coordinate, if reduction axes exist.

With one operand, omitted map means identity. With multiple operands, map is
required and its argument types follow operand order. No implicit multiplication.
If no axis is reduced, reduce is forbidden. Otherwise reduce is required.
No implicit addition.

Supported reducers are @add_f32 (identity 0), @minimum_f32 (identity +infinity),
and @maximum_f32 (identity -infinity). Their input and output type is f32.
The map's result type must match the reducer. The result tensor retains the
output axes and their extents.

For matrix multiplication:

```ttl
@einsum[row shared, shared column -> row column](a, b)
    map=@multiply_f32 reduce=@add_f32
```

the scalar C interpretation is:

```c
for (int row = 0; row < ROWS; ++row) {
    for (int column = 0; column < COLUMNS; ++column) {
        float accumulator = 0.0f;
        for (int shared = 0; shared < SHARED; ++shared)
            accumulator += a[row][shared] * b[shared][column];
        product[row][column] = accumulator;
    }
}
```

Output axes form outer loops and reduction axes inner loops. Each operand uses
only its own axes. Reduction starts from its identity. No output axes means a
scalar result; no reduction axes means a mapped result without an accumulator.

With identity map, `@einsum[row column -> row](matrix) reduce=@add_f32` means:

```c
for (int row = 0; row < ROWS; ++row) {
    float accumulator = 0.0f;
    for (int column = 0; column < COLUMNS; ++column)
        accumulator += matrix[row][column];
    row_sum[row] = accumulator;
}
```

In `@einsum[item, -> item](x, scale) map=@multiply_f32`, the empty pattern denotes
scalar scale. No axis is reduced:

```c
for (int item = 0; item < ITEMS; ++item)
    scaled[item] = x[item] * scale;
```

This expression is equivalent to `@multiply_f32(x, scale)`.

Reduction grouping is unspecified; different groupings can change FP32 rounding.
The C loops do not require sequential execution or bitwise-identical results.
Approximate operations follow the execution environment's documented rounding,
exceptional-value, and numerical-domain rules, without changing the mathematical
operation.

## 7. Selection and coordinate operations

### Constant selection

For x of type `f32[token hidden]`:

- `x[token=3]` removes token and reads its fourth element.
- `x[token=2:6]` retains token with extent 4 and reindexes from zero.

Axes must occur in x and cannot repeat in one selector. Bounds are integer
literals: index 0 <= i < extent; range 0 <= begin < end <= extent. Check them
statically. Other axes and dtype are unchanged.

With input `sequence[TOKENS][HIDDEN]`:

```c
/* sequence[token=3], with TOKENS >= 4 */
for (int hidden = 0; hidden < HIDDEN; ++hidden)
    selected[hidden] = sequence[3][hidden];

/* sequence[token=2:6], with TOKENS >= 6 */
for (int token = 0; token < 4; ++token)
    for (int hidden = 0; hidden < HIDDEN; ++hidden)
        sliced[token][hidden] = sequence[token + 2][hidden];
```

### Gather

`@gather[vocabulary -> batch token](embedding, indices)` reads embedding rows
using runtime indices. Indices have dtype i32; gather has two operands and
no map/reduce clause.

Let s be the single source axis, D the data axes, J the index axes, and R = D
minus s. Require s in D and not in J. The axes written after the arrow are
exactly J minus R. Shared axes have equal extents.
The output has data's dtype and axes R union J.

At each output coordinate, read j from indices, then data at s=j with retained
coordinates unchanged. Negative or out-of-range j is a runtime error.

For `embedding: f32[vocabulary hidden]` and `indices: i32[batch token]`,
the gather above produces `f32[batch token hidden]`:

```c
for (int batch = 0; batch < BATCH; ++batch) {
    for (int token = 0; token < TOKENS; ++token) {
        int j = indices[batch][token];
        if (j < 0 || j >= VOCABULARY)
            runtime_error(); /* terminates evaluation; does not return */
        for (int hidden = 0; hidden < HIDDEN; ++hidden)
            gathered[batch][token][hidden] = embedding[j][hidden];
    }
}
```

### Axis renaming and merging

`@rearrange` has one operand, one input/output pattern, and no map/reduce clauses.
It preserves dtype and element values, but may require a storage copy. Input
patterns name exactly the operand's axes, once each, using bare names. All axes
mentioned must be declared. Each expression preserves all axes, renames one,
or merges one ordered group. Other axes retain their identities, extents, and coordinates.

**Renaming.** Replace one input axis with one distinct output axis of equal
extent. The new identity must not already occur in the input. All other axes
appear on both sides unchanged. Corresponding input and output coordinates
are equal; only the axis identity changes.

```ttl
// key: f32[batch token head channel]; token and source have equal extents
@rearrange[batch token head channel -> batch source head channel](key)
```

```c
for (int batch = 0; batch < BATCH; ++batch)
    for (int source = 0; source < TOKENS; ++source)
        for (int head = 0; head < HEADS; ++head)
            for (int channel = 0; channel < CHANNELS; ++channel)
                renamed[batch][source][head][channel] = key[batch][source][head][channel];
```

The output's source coordinate selects the input's token coordinate.
Renaming does not identify token and source elsewhere in the program.

**Merging.** Replace two or more distinct input axes with one output axis
written `parent := [factor1 * factor2 * ...]`. The parent must not occur in
the input. Each factor must occur in the input and must not occur separately
in the output. All remaining axes appear on both sides unchanged. The declared
parent extent must equal the product of the factors' input extents.

Factor order determines coordinates, last factor fastest. Start with the first
coordinate; for each next factor, multiply by its extent and add its coordinate.
For two factors:

`parent_coordinate = factor1_coordinate * factor2_extent + factor2_coordinate`.

```ttl
// context: f32[batch token head channel]
// projection extent equals head extent times channel extent
@rearrange[batch token head channel -> batch token projection := [head * channel]](context)
```

```c
for (int batch = 0; batch < BATCH; ++batch)
    for (int token = 0; token < TOKENS; ++token)
        for (int head = 0; head < HEADS; ++head)
            for (int channel = 0; channel < CHANNELS; ++channel)
                merged[batch][token][head * CHANNELS + channel] =
                    context[batch][token][head][channel];
```

No other axes may appear or disappear. Products occur only on the output side;
inline extents such as `axis := 1` are forbidden in rearrangement patterns.
There is no splitting, unit-axis insertion/removal, replication, or concatenation.
A rename and a merge require separate expressions. Reordering preserved axes
in a pattern is the identity.

## 8. Errors

Violations of the lexical, grammar, name, type, shape, and operation rules above
are static errors. An intrinsic clause may occur at most once; unknown
intrinsics and forbidden clauses are errors.

At invocation, supplied values must match their declared shapes and dtypes.
An out-of-range gather index or a numerical-domain failure is a runtime error.
Invalid indices are not silently wrapped, clamped, padded, or truncated.
