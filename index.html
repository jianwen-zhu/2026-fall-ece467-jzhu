Overview

Compilers are more ubiquitous than most programmers realize. Their ideas power browser scripts, database queries, and tensor computations behind language models. ECE467 reveals the machinery you have taken for granted: how a system understands a program and turns it into work a machine can execute.

Follow the journey from source text to executable code: recognize tokens and grammatical structure, resolve names and check types, represent and analyze programs, and generate efficient instructions. Learn how runtime storage supports function calls and how optimizations improve a program while preserving its meaning. These ideas connect the code you write to its behavior on hardware.

Building a compiler develops both the art of programming — choosing representations and interfaces that make complex software manageable — and the science of programming — turning formal models into working algorithms. Both extend well beyond compiler development.

The project brings these foundations to the frontier of AI infrastructure. Build a compiler for a language that uses tensors—multidimensional arrays—to express computations in modern large language models. Run the generated programs on graphics processing units (GPUs). The payoff is measurable: correct results, wall-clock execution time, and speedups you can explain.

Project

Implement a compiler in C for ECE467 Tiny Tensor Language (TTL467). The language names tensor dimensions, operates on individual elements, and combines values through reductions such as sums. Your compiler emits programs in TileLang, a language for writing GPU kernels—functions executed by GPU threads. The supplied tools compile and run these kernels.

The target application is large language model inference: using a trained model to predict the next text token, such as a word or word fragment. Explore these computations in the Model Zoo, from matrix multiplication to attention and a GPT-2 forward pass. Your challenge: make them run faster while preserving their results.

Two tools connect your compiler to hardware. libttl (Tiny Tensor Library) provides a C interface for managing tensors and executing compiled programs. CloudMake runs your project's Make targets locally or in the cloud: edit on your computer, build and test on a GPU.

The project is split into five stages, each focused on a compiler phase. Together, they recover the program's structure, check its meaning, generate working code, and optimize it. Supplied intermediate files let you test each phase independently before connecting them.

01 · Lexical Analysis

Build a scanner that groups characters into tokens such as keywords, identifiers, and numbers. Report invalid input and pass the tokens to the parser.

02 · Syntax Analysis

Build a parser that checks the token stream against TTL467's grammar and constructs an abstract syntax tree representing declarations, expressions, and their relationships.

03 · Semantic Analysis

Resolve names, validate tensor operations, and diagnose violations of the language's rules. Determine the types and shapes needed for code generation.

04 · Code Generation

Translate the checked program into TileLang kernels and descriptions of how to connect them. Test the results across the required operations and shapes. Keep this correct, unoptimized version as your baseline.

05 · Code Optimization

Choose and implement compiler optimizations. Verify correctness, measure wall-clock execution time, and report reproducible speedups over your baseline on the same workloads and hardware. The leaderboard shows measured performance; your report explains which compiler decisions made the difference.

Use lab sessions to implement, test, and discuss your design. The tutorials prepare you with small programs to run, modify, and diagnose.
